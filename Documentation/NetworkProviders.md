# Native networking security providers

Foundation uses OpenSSL 3.5.9 LTS for TLS 1.3, certificate validation and cryptographic randomness, and MsQuic 2.6.4 for standards-based secure datagram transport. MsQuic implements QUIC reliability, congestion control and TLS; Foundation does not implement a custom reliable UDP protocol or cryptography. These are private C ABI dependencies of Foundation, not public engine interfaces.

Windows consumes the latest stable pinned native NuGet releases, MsQuic OpenSSL 2.6.4 and openssl-native 3.5.9. CMake stores their archives and verified contents in `Workspace/Nuget`, imports x64 or ARM64 native targets, and stages DLLs and symbols through shared runtime metadata. The official MsQuic DLL includes its own TLS implementation. Foundation's TLS and certificate validation use OpenSSL 3.5.9, with PKCS#12 and DER bytes at the MsQuic boundary. Ordinary Windows networking builds require no Python, Perl, NASM, or provider source compilation. See [Native NuGet dependencies](NuGet.md) for asset mappings, checksums, offline use and SDK export.

Linux and macOS verify pinned source archive hashes and compile OpenSSL and MsQuic in a private CMake binary-directory subtree. OpenSSL is shared by both source-built consumers. These provider builds require Python 3.12+, Perl with its standard build modules, make, Ninja, CMake, and a native compiler. Prefill `XII_NETWORK_DEPENDENCY_ARCHIVE_CACHE` for offline source builds. `XII_NETWORK_DEPENDENCY_BUILD_JOBS` bounds compilation parallelism.

Provider C ABI libraries use release binaries for every engine configuration. Static Foundation builds still require provider runtime libraries, staged beside consumers and included in SDK runtime metadata. Provider updates require archive verification, platform builds, TLS certificate and handshake regressions, and QUIC tests. Linux/macOS source identities remain recorded in `Utilities/Build/build_network_dependencies.py`, including the MsQuic source commit. Windows package identities and hashes are recorded in `NetworkDependencies.cmake`.

Credential snapshots load PEM certificate chains, private keys and explicit trust/CRL bundles once. Key file bytes and serialized private identity material are cleansed at release. Identity and trust changes require a new snapshot; active handshakes retain their original snapshot. No password is retained. Missing passwords never invoke an interactive prompt. Private key file access permissions remain the deployment's responsibility.

TLS 1.3 peer verification is mandatory. Server names are checked against DNS/IP subject alternative names; common-name fallback is disabled. Trust validation checks certificate purpose, validity and chain depth. CRL checking is enabled when an explicit revocation bundle is configured; validation does not fetch online intermediates or revocation information. Linux loads the configured system OpenSSL trust paths, Windows imports native ROOT stores, and macOS imports Security framework trust anchors. Imported roots establish certificate-chain trust; platform-specific dynamic trust policy is not evaluated by OpenSSL.

An explicit development CA can be used as a trust bundle. There is no certificate-verification bypass. Test certificates and private keys are generated in the test output directory and removed by their fixture owners.

Upstream references: [OpenSSL 3.5 documentation](https://docs.openssl.org/3.5/), [MsQuic 2.6.4](https://github.com/microsoft/msquic/tree/v2.6.4), [MsQuic certificate handling](https://github.com/microsoft/msquic/blob/v2.6.4/docs/api/QUIC_CONNECTION_EVENT.md). License copies are in `Foundation/Network/ThirdParty/` (OpenSSL: Apache-2.0; MsQuic: MIT).

## Caller-driven TLS records

`xiiNetworkTlsStream` owns a serialized TLS 1.3 connection with two fixed 64 KiB BIO directions. `Initialize` retains a shared immutable credential snapshot. Clients supply an explicit DNS name or IP SAN and an origin port. Servers require an identity; client certificates are required by default. ALPN must match exactly. `Handshake`, `Read`, `Write` and `Shutdown` never wait on a socket. `WouldBlock` means the owner must feed received ciphertext or drain produced ciphertext before retrying. Writes may accept a prefix of the supplied span; after `WouldBlock`, retry the same remaining bytes before starting another write.

Drain output into retained native send leases and feed completed native receive leases, preserving bytes that could not yet be accepted. `NotifyEndOfInput` follows all received ciphertext. TLS `close_notify` is distinct from unexpected raw EOF, which fails the connection. `Shutdown` produces `close_notify` and requires output drain and peer input until it succeeds or an external close deadline expires. The scheduling owner enforces handshake, idle and close deadlines; this record engine has no timers or threads.

Transport resumption is opt-in and has no early data. A bounded LRU cache belongs to each client credential snapshot, keyed by server name, port and ALPN. Cached native sessions and verified chains retain explicit references; cache replacement releases them. Resumed connections revalidate the cached peer chain and current validity against the retained trust snapshot. TLS ticket resumption is separate from application session recovery. An uncleanly terminated native TLS session may be marked non-resumable by OpenSSL.
