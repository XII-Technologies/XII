# Rendering configuration ownership inventory

This inventory audits the configuration surface before the subsystem migration. It supersedes the rendering classifications in [Settings.md](Settings.md). Pipeline topology, resource interfaces, hardware contracts, world simulation inputs, diagnostics, and user quality controls have different owners. A reflected pass property alone is not an instruction to expose it as a user setting.

## Scope and method

The first-party engine, engine/editor plugins, Editor, and sample source trees contain 24 CVar definitions. The GraphicsCore pass inventory covers 114 implementation files and 1007 reflected property declarations, including ports. Configuration headers and their member defaults/public control APIs were inspected alongside these registrations. Constructor and shader constants are classified by their consumer: algorithm/quality defaults are candidates for subsystem ownership; resource layouts, binding slots, numeric tolerances, hardware maxima and workgroup sizes remain implementation contracts.

## Existing structured owners

| Structure/API | Current storage and consumer | Migration responsibility |
| --- | --- | --- |
| `xiiRenderConfiguration` | Platform profile, scene/world, camera, viewport; merged in View, read by pipeline instance and DDGI/post passes | Replace scalar/sentinel fields with an owned typed subsystem collection and explicit property overrides; retain the existing scope chain and IPC/storage owners |
| `xiiRenderPipelineSettings` | Pipeline asset descriptor; device/output validation during compilation and frame preparation | Preserve contracts; add explicit authored subsystem defaults separately from device policies |
| `xiiRenderPipelineProfileConfig` | `xiiPlatformProfile`, DDL and runtime chunks | Shared project/platform defaults and compatibility migration |
| `xiiRenderPipelinePass` / `xiiRenderPipelineInstance` | Authored pass properties; per-view mutable instances | Resolve/apply typed controls before graph construction; retain instance resources when unaffected |
| `xiiView` / `xiiEngineViewConfig` | Runtime snapshot, editor viewport preferences and redraw IPC | Typed effective access, live preview, provenance and viewport persistence |
| `xiiRenderWorldSettingsComponent` / `xiiCameraComponent` | Scene/component serialization and inspector editing | Independent scene/camera overrides and normal document undo |
| `xiiDDGISettings` | CPU probe scheduler and pass defaults | Reuse the existing probe configuration; expose remaining supported DDGI scheduling/lighting controls |
| `xiiShadowCascadeSettings` | Directional shadow pass and projection utilities | Reuse cascade settings; keep light authoring/world light extraction separate |
| `xiiDisplayOutputSettings`, exposure and grading | Display manager defaults, view values, output pass defaults and parameter dictionaries | Consolidate render behavior in the typed scope resolution; preserve actual presentation ownership and output validation |
| `xiiSettings` | Reflected defaults, validation, cloning/DDL, apply notifications | Reuse for subsystem data and validation; do not add a second type registry |
| GPU residency / GAL streaming admission | GraphicsCore and Vulkan device state, currently controlled by saved CVars | Device-owned reflected policy, one instance per device, independent of views and pipeline assets |

## Capability boundaries

- The current surface provides deferred raster lighting, clustered local lights, screen-space irradiance, DDGI, explicit ray-traced irradiance, sparse voxel scheduling, raster/virtual shadow infrastructure, SSR with temporal accumulation, AO with screen/ray paths, atmosphere lookup tables, temporal AA, spatial upscaling, exposure, bloom, tone mapping, grading, sensors, transparency/refraction and visualization. Authored pipeline support and device features still constrain each selection.
- A volumetric composition operation does not establish a volumetric fog generation implementation. No unsupported fog quality, DLSS, FSR, path-traced reflection, or alternative forward renderer should be invented.
- Scene physical camera, lights, atmosphere, materials, sensor calibration and particle simulation retain their authoritative scene/component/resource owners. View quality configuration must not silently replace physical authored inputs.
- Device memory limits, upload budgets and texture/geometry cache policies must not be cloned into every view. VSync and frame pacing retain presentation/application ownership.
