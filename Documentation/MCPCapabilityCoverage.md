# XII MCP capability coverage

The [MCP guide](ModelContextProtocol.md) lists the registered tool names, transports and setup. Runtime capabilities act on a running process and are transient. Editor capabilities operate on the active project and use document commands for persistent changes.

| Domain and owning API | Discovery and inspection | Changes, execution and capture | Coverage limits |
| --- | --- | --- | --- |
| Application and plugins (`xiiGameApplicationBase`, `xiiPlugin`, `xiiSubSystem`) | `runtime.status`, `runtime.subsystems`, `runtime.diagnostics` expose frame time, startup phases, loaded plugins and subsystem dependencies. | | Plugin loading, unloading and application shutdown require the host's lifecycle controls. |
| RTTI (`xiiRTTI`, `xiiReflectionUtils`) | `runtime.types` filters by base, owner and name. `runtime.type` reports inheritance, allocation metadata and JSON Schemas for exposed members. | Document and component operations use the same value representation. | RTTI allocation metadata does not grant permission to instantiate a class. The catalog exposes no arbitrary function calls or pointer properties. Containers and nested writes remain limited. |
| Worlds and components (`xiiWorld`, `xiiGameObject`, `xiiComponentManagerBase`) | World UUIDs, object handles, paged hierarchy and components, transforms and reflected member values. Component schemas identify members eligible for live editing. | `runtime.edit_object` covers lifecycle, transforms and reparenting. `runtime.edit_objects` applies bounded batches. `runtime.edit_component` attaches, activates, removes and sets eligible reflected values. | Attachment requires a dynamic owner. Live batches keep previously applied edits on failure. Property writes require the current component ID and exact RTTI type, and are limited to explicitly opted-in top-level members. |
| Simulation and world modules (`xiiWorld`, `xiiClock`, `xiiWorldModule`, `xiiPhysicsWorldModuleInterface`) | Per-world timing and state, active rigid-body backend and gravity. Read-only queries provide nearest ray and sphere-sweep hits and sphere overlap. | `runtime.simulation` controls enabled state, pause and speed. | Other shape queries, body controls, contact events, model-based simulator controls and single-step operations remain open. |
| Resources (`xiiResourceManager`, `xiiResource::ContentStats`) | Runtime resource RTTI, paged ID search, asynchronous state, description, quality and memory. | `runtime.reload_resource` asks the resource manager for an ordinary reload. | No universal dependency or failure-log API for runtime resources. Asset transformation reports Editor-side dependencies and errors. |
| Graphics (`xiiGALDevice`, `xiiRenderWorldModule`, `xiiView`, render graph diagnostics) | Adapter, feature support, heaps, camera and resolution, render mode, loaded pipeline ID. | Capture a graph and available GPU timings or request a game-window screenshot. | The world module returns the first view per usage hint. Render configuration editing and frame-by-frame resource inspection remain open. |
| Diagnostics (`xiiMemoryTracker`, `xiiStats`, `xiiGlobalLog`, `xiiCVar`) | Bounded allocator and performance counters, numeric and Boolean CVars and recent warnings/errors. | Log retrieval and GPU timing snapshots require capture permission. | String CVars are redacted. CPU profiling capture and CVar writes remain open. |
| Input (`xiiInputManager`) | Input sets, action state and bindings, exclusive set, and registered slot names. | Change or clear one binding on an existing action. | Edits are transient. |
| Animation, audio, scripting and networking | RTTI and subsystem discovery show the types and subsystem names registered by the target. | | Domain-specific controls and diagnostics remain open. |
| Editor project and builds (`xiiToolsProject`, `xiiAssetCurator`, `xiiCppProject`, Editor plugin bundles) | Manifest, project generation, document types, asset profiles, available and selected bundles, engine readiness, C++ paths and solution state. | Editor plugin selection enables Local MCP. Per-user project preferences grant native edit and asset processing. | No MCP project switching or asynchronous C++ build execution. The current Editor compile entry point assumes the Qt thread and blocks until the build completes. |
| Editor documents and scenes (`xiiDocumentManager`, `xiiObjectAccessorBase`, `xiiCommandHistory`) | Open documents, available file extensions, selection, object hierarchy, reflected member schemas, dirty and undo/redo state. | Create and open new documents, open indexed assets, close saved main documents, edit supported document members, perform transactional scene batches, undo/redo and queue saves. | Creation requires a new project-relative path in an existing directory. Mutations require the approved project and current generation, and changes to an open document require current session and revision tokens. Layer-specific lifecycle and prefab-specific commands remain open. |
| Materials, shaders, pipelines and graph assets (`xiiDocumentNodeManager`, `xiiNodeCommandAccessor`) | Indexed dependencies, reflected members, generated outputs and transform messages. Node documents with a node command accessor expose pins, links and creation templates. | Edit reflected members, create template nodes, connect and disconnect pins, remove nodes and queue asset processing. | Standalone shader permutation compilation remains open. |
| Editor viewport (`xiiQtEngineDocumentWindow`, `xiiQtEngineViewWidget`) | `editor.viewport` resolves the active or requested document and reads viewport IDs, camera state, resolution, render mode and effective subsystem settings. `editor.documents` reports selection. | | Camera and render configuration changes, screenshots, simulation and play commands remain open. |
| Gateway and transport (`xiiNetworkReflectionEndpoint`, XII TCP, Qt) | Asynchronous identity and capability discovery, instance UUID routing, session overview and searchable activity. | HTTP and stdio invocation, editable Qt listener settings, per-target connect/disconnect, queue cancellation and best-effort cancellation of the current GUI invocation. | Forwarded invocations still serialize. Stateful HTTP sessions are visible. SSE, external client cancellation of running calls and stateless client tracking remain open. |
